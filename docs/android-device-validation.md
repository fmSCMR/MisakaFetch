# Android 设备验收

MisakaFetch 1.0.0 已完成 Android 真机验证。以下清单用于后续版本回归检查；设备结果适用于实际测试的设备与系统版本。

## 安装与启动

以下为本地开发回归流程；命令使用 flutter build apk --release 生成的 APK。下载的发行包可直接在手机安装。

在项目根目录执行 `adb devices -l`，确认目标设备状态为 device；unauthorized 表示需要在手机上授权，offline 需要先恢复连接。多设备时每条 adb 命令增加 `-s <设备序列号>`，避免安装到错误设备。

```powershell
adb install -r build/app/outputs/flutter-apk/app-release.apk
adb shell am start -n app.misakafetch/.MainActivity
```

APK 为项目专用签名的 Release 构建，包名为 `app.misakafetch`。若安装报告签名不一致，不自动卸载已有应用；先确认已有应用来源和需要保留的数据。

## 核心验收

| 操作 | 预期 |
| --- | --- |
| 输入 BV1Q541167Qg 并提取 | 显示标题、UP 主、BV、完整封面与原始图片地址 |
| 连续点击提取 | 加载期间按钮禁用，没有重复请求 |
| 点击复制图片链接 | 剪贴板内容与页面原始图片地址一致 |
| Android 10+ 点击保存原图 | 提示保存成功，相册或 Pictures/MisakaFetch 中有完整图片，无相册读取或广泛存储权限请求 |
| Android 7–9 点击保存原图 | 打开系统另存为，选择位置后保存原图；取消不显示保存成功 |
| 再次保存同一封面 | 完成第二次保存，原文件不被应用直接覆盖；系统提供者处理重名 |
| 关于页点击 GitHub 项目 | 在系统浏览器中打开仓库；无法打开时提示复制地址 |
| 切换主题、横竖屏、滚动 | 信息与按钮可访问，无溢出或崩溃 |

## 原始字节验证

确认本机样例与手机提取的原始封面地址一致。将手机本次保存的图片通过 USB / 文件管理器复制到 build/qa 下，与本机下载的原图比较：

```powershell
Get-FileHash build/qa/cover.bin -Algorithm SHA256
Get-FileHash build/qa/android-saved.jpg -Algorithm SHA256
```

只有两份文件 SHA-256 一致，才记录原始字节保存通过；扩展名可能随图片类型变化。若远端封面发生变化，应重新下载当前原图再比较，不把旧样例差异误判为重新压缩。文件管理器传输使用原文件，避免通过会压缩图片的聊天应用中转。

## 错误与恢复

- 空输入、无关文本及格式错误的 BV：显示中文提示，应用仍可继续使用。
- 断网后提取：显示网络或超时提示；恢复网络后可重新提取。
- 封面加载失败：保留视频信息与复制链接，保存按钮不可用；重新加载成功后可保存。
- 保存期间重复点击：不会发起第二次写入；完成后恢复按钮。
- 在可复现的不可写位置或空间不足情况下保存：显示保存失败，不能误报成功；恢复条件后可再次保存。无需为了测试耗尽手机存储或修改系统目录。

## 记录结果

记录设备 Android 版本、测试 APK 版本、每项通过 / 失败、失败提示，以及原图和保存文件的 SHA-256。日志只截取应用相关错误，不收集与测试无关的设备内容。截图要求见 [截图说明](screenshots/README.md)。

Android 10+ 与 Android 7–9 使用不同原生存储路径，一台设备的通过结果只覆盖其所在版本分支。
